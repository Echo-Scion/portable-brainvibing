## 🛡️ Unified 5-Domain Interface Review Protocol (`better-interface` + `superfuture-design-review`)

Review the interface as **one integrated system** in this strict foundational order (never let surface polish hide accessibility or layout failures):
1. **Accessibility (WCAG 2.2 AA & APCA)**: Native elements first (`<button>`, `<a href>`, never `<div onClick>`), `:focus-visible` ring ($\ge 2\text{px}$), focus not obscured by sticky chrome (2.4.11), roving `tabindex` (`0`/`-1` only), modal `inert` + focus restoration, $\ge 44\times 44\text{px}$ touch / $\ge 40\times 40\text{px}$ desktop targets, persistent `<label>`, non-drag alternative (2.5.7), paste allowed on auth/OTP fields (3.3.8), and `@media (prefers-reduced-motion: no-preference)`.
2. **Layout & Task Topology**: Task-fitting layout model (Table, Split View, Rail, Command Surface vs Bento), grouped by whitespace ($\ge 2\times$ inter-group vs intra-group gap) rather than redundant borders/cards, shared alignment edges, logical RTL-ready properties (`margin-inline-start`), and content-driven breakpoints.
3. **UX Writing & Microcopy (`Balise`)**: Stake-adapted tone, verb-first buttons, destructive confirmations repeating the exact consequence (`"Delete project"`), instructional field-adjacent errors, and 4 distinct empty states (*First-time*, *Filtered-to-empty*, *Nothing-yet*, *No-permission*).
4. **Typography**: $\le 3$ typefaces, semantic type scale, unitless line-height (`1.1–1.2` display, `1.5–1.6` body, $\ge 1.4$ for 3+ wrapped lines), `45ch–75ch` measure cap, `text-wrap: balance` on headings / `pretty` on descriptions, `tabular-nums` on dynamic counters, and `16px` mobile input floor.
5. **UI Polish & 4-Gate Motion**: Concentric radii (`outer = inner + padding`), optical icon padding (`icon-side = text-side - 2px`), `oklch` shadow-borders, `1px` neutral image outlines (`outline-black/10 dark:outline-white/10`), stroke weight matched to text weight (`1.5px`/`2px`/`2.5px`), and 4-Gate Motion compliance (`100+/day = 0ms`, `scale(0.96)` + `static` prop, `initial={false}` on `AnimatePresence`).

### Mandatory Audit Report Structure
1. **Scope, Mode & Coverage Table**: `quick` (cap 5 HIGH/MEDIUM findings) or `full` (cap 15 across all 5 domains + 6 state families).
2. **Strengths (2–4 Items)**: Explicitly name what already works well so revisions never break established craft.
3. **Prioritized Findings Table** (Ranked by Severity `HIGH /Blocking` $\to$ `MEDIUM /Important` $\to$ `LOW /Polish`, then leverage):
   - Columns: `# | Severity | Domain | Classification (Confirmed Deviation / Likely Deviation / Recommendation) | Location (file:line) | Current | Proposed Fix | Why`
   - Flag any unverified context with `[assumed]` or `[needs confirmation]`.
4. **Considered but Rejected Table (1–5 Candidates)**: Document borderline changes deliberately rejected because existing tokens/conventions are intentional or would add complexity without user benefit.
5. **Single Highest-Leverage First Fix & Verdict**: Close with `Block`, `Needs changes`, or `Approve`.

## 🛡️ Behavioral Validations (Nudge Mode)
- **Cognitive Load**: NEVER allow task dumps. Show the 1 most critical item if pending list is large.
- **Respect Focus**: NEVER suggest tone-deaf interruptions during user focus hours.
- **Off-Ramps**: ALWAYS offer an "opt-out" completion (e.g., "call it for the day?").
- **Default Bias**: Leverage defaults to reduce user decision fatigue.
